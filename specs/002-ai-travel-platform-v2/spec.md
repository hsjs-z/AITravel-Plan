# Feature Specification: AI 旅行平台 v2

**Feature Branch**: `002-ai-travel-platform-v2`

**Created**: 2026-10-17

**Status**: Approved for implementation planning

**Input**: v1 已交付 `3df09f3`。v2 聚焦 AI 规划体验重做、全国景区数据管道、
高德地图集成与 Spring AI 迁移；不得回退 v1 已验收行为。

## Scope and Non-Regression

### In scope

- 手动触发全国热门景区种子导入，resource 成为规划与预订的唯一事实源。
- Spring AI 1.0 GA + DeepSeek 真工具调用，替换直连 DeepSeek 的 `RestTemplate`。
- 规划表单、结果页与地图体验重做。
- 行程项增加时段与时段内排序，结果页支持草稿态添加/删除。
- 交易链路收敛为门票交易。
- user-auth 用户持久化到 MySQL，并增加管理员角色。

### Out of scope

- 结果页分享功能。
- “地名”板块。
- 酒店类行程项和酒店交易。
- 定时景区导入任务。
- 免费景区的零元支付链路。
- 商家端、真实支付通道、退款策略变更。

### Non-regression checklist

- 越权访问仍统一返回 404。
- 支付终态守卫不变：`SUCCEEDED/FAILED` 不可逆，重复/乱序回调不翻状态。
- 支付、退款、订单创建的幂等键语义不变。
- Outbox 事务内落库 + 轮询投递 + 消费端去重不变。
- AI 给出的资源 ID 必须在本次工具返回结果内；非法 ID 不得绑定库存。
- `@Qualifier("applicationTaskExecutor")` 显式注入修复不得回退。
- Prometheus、Grafana、Tempo 三件套及 traceId 跨服务透传不得回退。
- 既有登录、注册、内容检索、行程查看/编辑/确认、订单、支付、通知页面行为不得回退。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 基于真实库存生成可执行行程 (Priority: P1)

游客选择目的地、天数、人数、节奏并填写偏好后提交规划。系统在后台调用 AI，
AI 自主查询平台上架景区，并基于真实返回的名称、级别、称号、门票价、坐标和规格
生成每日有序景点列表。用户看到的方案不再依赖 AI 凭空编造的资源。

**Why this priority**: 这是 v2 的核心体验，也是“resource 是唯一事实源”的关键验证。

**Independent Test**: 使用 mock 和 DeepSeek 两种规划模式各提交一次任务，
都能得到按天有序景点列表；未匹配景点仍展示但不可预订；非法 ID 不会进入行程项。

**Acceptance Scenarios**:

1. **Given** 目的地有上架景区，**When** 用户提交规划，**Then** 结果包含每天的
   有序景点列表，未匹配项不携带任何库存 ID。
2. **Given** AI 返回了本次工具结果之外的 `resourceId/specId`，**When** 服务端落草稿，
   **Then** 两个 ID 都被置空，景点仍以未匹配状态展示。
3. **Given** 规划服务处于 mock 模式，**When** 用户提交非云南目的地，
   **Then** mock 也按该目的地候选数据生成，不固定返回云南资源。

---

### User Story 2 - 用结构化表单表达旅行偏好 (Priority: P1)

游客用按钮选择 1–10 天游玩天数、16 个热门地区之一或自由输入中国国内地区，
选择慵懒/散步/精彩节奏，填写风格、兴趣、预算和特殊要求。人数默认 1。

**Why this priority**: 表单决定 AI 输出的容量与质量，是规划体验的入口。

**Independent Test**: 不依赖 AI，仅验证表单选项、默认值、提交载荷和校验提示。

**Acceptance Scenarios**:

1. **Given** 用户打开规划页，**When** 页面加载，**Then** 天数只能选 1–10，
   人数默认 1，节奏三选一，没有独立预算字段。
2. **Given** 用户选择热门地区，**When** 提交，**Then** 目的地等于该城市名。
3. **Given** 用户自由输入非中国国内地区，**When** 提交，**Then** 系统拒绝并提示
   仅支持中国国内目的地。

---

### User Story 3 - 查看、定位并调整草稿行程 (Priority: P1)

游客在结果页按天查看上午/下午/晚上安排，点击景点定位到地图；草稿态可以从库存
添加景点或删除草稿中的景点；确认或锁定后页面只读。

**Why this priority**: 结果页是 v2 体验重做的主体，也是规划到预订的衔接点。

**Independent Test**: 用一份草稿和一个已确认行程分别打开结果页，验证添加/删除
按钮的可见性、地图定位、免费/未匹配文案和只读行为。

**Acceptance Scenarios**:

1. **Given** 草稿行程，**When** 用户点击某时段“添加”，**Then** 从库存检索并加入
   一个匹配景区；该时段超过 3 个时拒绝。
2. **Given** 草稿行程，**When** 用户点击某景点“删除”，**Then** 该行程项被移除，
   其他时段和排序保持正确。
3. **Given** 已确认或已锁定行程，**When** 用户打开结果页，**Then** 添加和删除都隐藏，
   页面没有任何编辑入口。
4. **Given** 景点有坐标，**When** 用户点击“点击查看地图位置”，**Then** 地图定位到
   该坐标；无坐标时显示“坐标待补”。
5. **Given** 免费景点，**When** 用户查看卡片，**Then** 显示“免费/无需购票”，
   可加入行程；未匹配景点显示“暂不可预订/票价以官方为准”，两者文案不得混用。

---

### User Story 4 - 只预订门票 (Priority: P1)

游客对已确认行程发起一键预订，系统只接受门票行程项；门票默认数量等于出行人数。
酒店种子可以继续存在，但不再产生酒店行程项或酒店订单明细。

**Why this priority**: 交易链路的类型收敛会直接影响库存锁定和支付。

**Independent Test**: 用门票行程和伪造的酒店行程分别下单，前者成功，后者被拒绝；
原有 Saga、幂等、支付终态测试全部通过。

**Acceptance Scenarios**:

1. **Given** 已确认行程只含可预订门票，**When** 用户一键预订，**Then** 每个门票项
   默认数量等于出行人数。
2. **Given** 请求中包含酒店或车票资源，**When** 系统锁定库存，**Then** 请求被拒绝，
   订单不产生对应明细。
3. **Given** 重复提交同一行程，**When** 请求到达，**Then** 仍只产生一张订单。

---

### User Story 5 - 管理员一次性导入全国景区 (Priority: P2)

管理员手动触发导入。系统按省分批调用 AI 生成景区数据，做字段校验和高德地理编码，
由服务端写入 resource，并产出可查询的批次报告。

**Why this priority**: 没有可靠的全量景区目录，规划与门票交易无法覆盖全国。

**Independent Test**: 使用管理员 token 触发一次导入，轮询报告；检查 34 个省级行政区、
每省 6 个、约 204 条、16 个热门城市覆盖、坐标待补和重跑跳过。

**Acceptance Scenarios**:

1. **Given** 管理员已登录，**When** 触发导入，**Then** 返回 `202 + runId`，
   不阻塞 HTTP 请求。
2. **Given** 某批 JSON 映射失败，**When** 系统处理该批，**Then** 整批重试 1 次；
   仍失败则报告该批失败并继续后续批次。
3. **Given** 某景区查不到坐标，**When** 入库，**Then** 记录仍写入并标记“坐标待补”。
4. **Given** 同一景区已存在或已被人工修改，**When** 重跑导入，**Then** 不插重、
   不覆盖人工修改，报告中计入跳过。
5. **Given** 非管理员或未登录用户，**When** 调用导入接口，**Then** 分别返回 404 或 401。

---

### User Story 6 - 账号跨重启保留并获得管理员权限 (Priority: P2)

游客注册后，账号在服务重启后仍可登录；管理员账号通过环境变量引导创建，
可调用管理接口，普通用户不可调用。

**Why this priority**: 内存用户存储是 v1 明确记录的技术债，管理接口也需要可靠的权限边界。

**Independent Test**: 注册用户、重启 user-auth、再次登录；用管理员和普通用户分别访问导入接口。

**Acceptance Scenarios**:

1. **Given** 用户注册成功，**When** user-auth 重启，**Then** 同一邮箱和密码仍可登录。
2. **Given** 管理员通过环境变量引导创建，**When** 管理员登录，**Then** token 带管理员角色。
3. **Given** 普通用户登录，**When** 访问 `/admin/**`，**Then** 返回 404。

---

### Edge Cases

- 时段装箱：景点时长超过当前时段剩余容量时，不得把单个景点拆分到多个时段。
- 首个 4h 景点在 4h 上午容量且上午为空时，必须留在上午，不能被无理由甩到下午。
- “慵懒”档晚上容量为 0，结果页仍渲染空晚上区块；这是明确取舍，不是缺数据。
- 当前时段放不下但后续时段可放下时，允许按顺序溢出到后续时段；
  一旦溢出，后续景点不得回填到更早时段。
- 所有可用时段都放不下时，从该景点起停止当天装箱，剩余景点不落库并写入警告。
- 免费景点可加入行程，但 `resourceId` 可存在、`specId` 为空，且永不进入支付。
- 未匹配景点可加入行程，但 `resourceId/specId` 都为 null。
- 高德 Web 服务 key 缺失时导入运行失败并提示配置错误；key 有效但地理编码失败或
  港澳台覆盖不足时，不影响资源入库，统一标记坐标待补。
- 地图 JS key 缺失时，结果页仍可用，地图区域显示配置提示。
- 重复触发导入时，系统拒绝并发运行；已结束的运行可以重新触发。
- 导入重跑不覆盖人工修改，包括人工填写的 `image_url`。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-V2-001**: v2 表单 MUST 只提供 1–10 天；服务端保留 1–30 的旧请求兼容，
  v2 新表单不得提交 11–30 天。
- **FR-V2-002**: 用户 MUST 能从 16 个固定热门地区中选择，或自由输入中国国内地区。
- **FR-V2-003**: 用户 MUST 能三选一游览节奏：慵懒、散步、精彩。
- **FR-V2-004**: 用户 MUST 能用自由文本表达风格、兴趣、预算和特殊要求；
  系统 MUST NOT 再要求独立预算数值。
- **FR-V2-005**: 出行人数 MUST 默认 1，并保留 1–20 的可调整范围。
- **FR-V2-006**: AI MUST 输出每天有序景点列表，每项含名称、建议时长、简介、
  参考票价和可选资源绑定。
- **FR-V2-007**: 时段分配 MUST 由代码完成，MUST NOT 由 AI 决定上午/下午/晚上。
- **FR-V2-008**: 每个时段 MUST 最多 3 个景点；每日景点数量上限由节奏决定。
- **FR-V2-009**: 装箱 MUST 按 AI 顺序进行，MUST NOT 拆分单个景点，MUST NOT 回填到更早时段。
- **FR-V2-010**: 慵懒档每日最多 2 个景点、4 小时；散步档最多 4 个、8 小时；
  精彩档最多 6 个、12 小时。
- **FR-V2-011**: 慵懒档晚上容量 MUST 为 0，页面 MUST 继续显示空晚上区块。
- **FR-V2-012**: 匹配景点 MUST 从库存读取真实价格、图片、坐标和 `specId`。
- **FR-V2-013**: 未匹配景点 MUST 展示名称/简介/时长，标记“暂不可预订”，
  票价显示“以官方为准”，资源 ID MUST 为空。
- **FR-V2-014**: 免费景点 MUST 显示“免费/无需购票”，可加入行程，但不进入支付链路。
- **FR-V2-015**: 服务端 MUST 只接受本次 AI 工具返回结果内的 `resourceId/specId`。
- **FR-V2-016**: 结果页 MUST 展示按天折叠、上午/下午/晚上分区、景点卡片和 AI 旅行建议。
- **FR-V2-017**: 结果页 MUST 提供常驻地图；点击景点定位到坐标，无坐标时明确提示。
- **FR-V2-018**: 草稿态结果页 MUST 支持按库存添加景点和删除草稿景点；
  行程确认/锁定后 MUST 隐藏添加和删除，整页只读。
- **FR-V2-019**: 添加 MUST 复用或扩展 itinerary 行程项接口；每时段最多 3 个。
- **FR-V2-020**: 结果页 MUST NOT 提供分享；MUST NOT 新增“地名”板块。
- **FR-V2-021**: 管理员 MUST 能通过手动接口触发景区导入，无需定时任务。
- **FR-V2-022**: 导入 MUST 覆盖 34 个省级行政区，每省 6 个热门景区，约 204 条。
- **FR-V2-023**: 导入 MUST 按每批 4–6 省调用 AI；JSON 映射失败 MUST 整批重试 1 次。
- **FR-V2-024**: 导入 MUST 由服务端写库，AI MUST NOT 直接写数据库。
- **FR-V2-025**: 字段校验不合格的景区 MUST 被丢弃并计入报告。
- **FR-V2-026**: 坐标查询 MUST 使用景区名称+城市；查不到时 MUST 入库并标记坐标待补。
- **FR-V2-027**: resource MUST 以名称+城市为唯一键；重跑 MUST insert-or-skip，
  MUST NOT 覆盖人工修改。
- **FR-V2-028**: 导入 MUST 产出每批成功/重试/失败/跳过明细和总计报告。
- **FR-V2-029**: 页面 MUST 标注“数据由 AI 生成，仅供参考”。
- **FR-V2-030**: 规划 MUST 使用 Spring AI 1.0 GA 调用 DeepSeek；
  MUST NOT 保留 `RestTemplate` 直连 DeepSeek。
- **FR-V2-031**: 规划 MUST 注册 `searchAttractions(destination)` 工具；
  AI MUST 能自主调用并基于真实返回数据组装方案。
- **FR-V2-032**: mock/deepseek 切换 MUST 保持 `PLANNER_PLANNER` 配置语义。
- **FR-V2-033**: 交易链路 MUST 只接受门票；酒店/车票 MUST 无法产生 v2 订单明细。
- **FR-V2-034**: 门票默认数量 MUST 等于出行人数。
- **FR-V2-035**: Saga、库存锁、退款、幂等、支付终态守卫 MUST 保持 v1 语义。
- **FR-V2-036**: user-auth 用户 MUST 持久化到 MySQL，注册/登录行为不变。
- **FR-V2-037**: 管理员 MUST 通过 role + JWT claim + 环境变量引导获得管理权限。
- **FR-V2-038**: 省级“云南”自由输入 MUST 能检索省级景区；按钮“丽江”
  MUST 能检索城市景区；旧 v1 云南数据 MUST 正确回填 province/city。
- **FR-V2-039**: 既有 8 个已验收页面 MUST 保持原有功能行为。
- **FR-V2-040**: Prometheus、Grafana、Tempo MUST 继续可用；新增导入和工具调用
  MUST 有可观测证据。

### Key Entities

- **Resource**: 平台可展示资源；v2 增加 `ATTRACTION`，含省份、城市、级别、称号、
  简介、建议时长、参考票价、坐标、坐标状态和图片地址。
- **Spec**: 门票规格；付费景区至少有一个 `TICKET_TYPE` 规格。
- **PlanningTask**: 规划请求与结果；含节奏、可选预算、自由文本偏好和归一化结果。
- **ItineraryItem**: 行程项；含名称、简介、建议时长、资源绑定、时段和时段内排序。
- **SeedRun**: 一次景区导入运行；含状态、批次报告、重试/失败/跳过明细。
- **User**: 平台账号；含持久化身份和管理员/普通用户角色。

## 16 个热门地区

北京、上海、西安、成都、重庆、杭州、苏州、南京、厦门、青岛、长沙、武汉、广州、
桂林、丽江、三亚。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 34 个省级行政区均有导入记录；每省 6 条；总计约 204 条。
- **SC-002**: 16 个热门地区在导入后均至少命中 1 个上架景区；北京和丽江继续命中
  既有 v1 数据。
- **SC-003**: 重跑导入后 `(name, city)` 重复插入数为 0，人工修改被覆盖数为 0。
- **SC-004**: 白名单测试中，工具结果之外的资源 ID 绑定率为 0。
- **SC-005**: 门票订单的酒店/车票明细数为 0；默认门票数量与出行人数一致。
- **SC-006**: user-auth 重启后注册用户登录成功率为 100%。
- **SC-007**: 结果页草稿态添加/删除可用；确认/锁定后添加/删除入口数为 0。
- **SC-008**: 免费与未匹配文案在自动化测试和人工验收中可区分。
- **SC-009**: 装箱边界测试覆盖 4h 首个景点、时段剩余不足、慵懒晚上 0、超时未放置
  四类场景且全部通过。
- **SC-010**: v1 主链路回归、Prometheus 指标、Tempo 链路验证全部通过后，
  才允许进入 V2-03。

## Assumptions

- 高德坐标使用 GCJ-02，与 Web JS 地图坐标体系一致。
- 景区图片不在本轮生成或上传；`image_url` 可为空，前端显示占位图。
- 导入的付费景区创建默认“成人票”规格和未来 365 天库存；免费景区不创建交易规格。
- 自由输入目的地以中国省级行政区或导入城市目录校验，不做海外目的地降级。
- 旧酒店种子保留在库，但不参与 v2 规划、行程项和订单。
- 当前日期 2026-10-17；v2 依赖版本以 V2-02 开工时再次核实的 Maven Central 记录为准。
